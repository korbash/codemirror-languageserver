# Руководство по изучению ответов LSP сервера

Это руководство поможет вам изучить ответы Language Server Protocol (LSP) сервера с помощью специальных тестов, разработанных для визуального анализа.

## Зачем изучать ответы сервера?

При разработке LSP интеграций важно понимать:

- **Какие данные** возвращает сервер для автодополнения
- **Как структурированы** hover подсказки
- **Где находятся** определения символов
- **Сколько ссылок** найдено на конкретный символ
- **Какие ошибки** возникают при обработке запросов

## Типы тестов

### 🔍 Детальные тесты (`test:detailed`)

**Назначение**: Комплексное изучение всех типов LSP ответов

```bash
npm run test:detailed
```

**Что показывает**:

- Полные JSON структуры ответов
- Типы автодополнения с документацией
- Hover информацию с диапазонами
- Позиции определений и ссылок
- Статистику по количеству результатов

**Когда использовать**: Когда нужно понять полную структуру ответов сервера.

### 🎯 Демонстрационные тесты (`test:demo`)

**Назначение**: Быстрая проверка основной функциональности

```bash
npm run test:demo
```

**Что показывает**:

- Базовые ответы на простом коде
- Пошаговое выполнение запросов
- Состояние соединения с сервером
- Простую диагностику проблем

**Когда использовать**: Для быстрой проверки работоспособности сервера.

### 🐛 Отладочные тесты (`test:debug`)

**Назначение**: Глубокая диагностика проблем

```bash
npm run test:debug
```

**Что показывает**:

- Полное логирование каждого шага
- Анализ типов данных в ответах
- Детальную информацию об ошибках
- Состояние WebSocket соединения
- Параметры каждого запроса

**Когда использовать**: При возникновении проблем с сервером или неожиданных ответов.

## Интерпретация результатов

### Успешные ответы автодополнения

```json
{
    "items": [
        {
            "label": "sys",
            "kind": 9,
            "detail": "module sys",
            "documentation": "System-specific parameters and functions",
            "insertText": "sys"
        }
    ],
    "isIncomplete": false
}
```

**Ключевые поля**:

- `label` - отображаемый текст
- `kind` - тип элемента (9 = Module)
- `detail` - дополнительная информация
- `documentation` - описание
- `insertText` - текст для вставки

### Успешные ответы hover

````json
{
    "contents": {
        "kind": "markdown",
        "value": "```python\ndef test() -> int\n```\n\nОписание функции"
    },
    "range": {
        "start": { "line": 2, "character": 4 },
        "end": { "line": 2, "character": 8 }
    }
}
````

**Ключевые поля**:

- `contents` - содержимое подсказки
- `range` - диапазон текста, к которому относится hover

### Пустые результаты

Если сервер возвращает `null` или пустой массив:

```
❌ Результат равен null - автодополнение не доступно
```

**Возможные причины**:

- Неправильная позиция курсора
- Контекст недостаточен для анализа
- Сервер не поддерживает данный тип запроса

## Практические примеры

### Изучение автодополнения импортов

1. Запустите детальные тесты:

    ```bash
    npm run test:detailed
    ```

2. Найдите секцию "АВТОДОПОЛНЕНИЕ ПОСЛЕ import":

    ```
    🔍 Позиция запроса: строка 1, символ 7 (после "import ")
    📦 ПОЛНЫЙ JSON ОТВЕТ:
    ```

3. Анализируйте структуру ответа для понимания доступных модулей

### Диагностика проблем с hover

1. Запустите отладочные тесты:

    ```bash
    npm run test:debug
    ```

2. Найдите секцию "ОТЛАДКА HOVER":

    ```
    📊 Анализ hover ответа:
       - Тип: object
       - Конструктор: Object
       - Является null: false
    ```

3. Проверьте, есть ли содержимое в ответе

### Проверка доступности сервера

Если видите сообщение:

```
🔌 LSP сервер недоступен на адресе: ws://127.0.0.1:8000/lsp/python
💡 Убедитесь, что сервер запущен и слушает указанный порт
```

**Решение**:

1. Убедитесь, что LSP сервер запущен
2. Проверьте правильность URL в тестах
3. Убедитесь, что порт не заблокирован

## Советы по отладке

### 1. Начните с простого

Используйте демонстрационные тесты для базовой проверки:

```bash
npm run test:demo
```

### 2. Проверьте параметры запроса

В отладочных тестах всегда выводятся параметры:

```json
{
    "textDocument": { "uri": "file:///debug.py" },
    "position": { "line": 0, "character": 7 }
}
```

Убедитесь, что позиция корректна для вашего кода.

### 3. Анализируйте тип ответа

Обращайте внимание на анализ типов:

```
📊 Анализ ответа:
   - Тип: object
   - Является массивом: false
   - Является null: false
```

### 4. Изучайте логи соединения

Следите за состоянием соединения:

```
[ConnectionManager:INFO] State changed: connecting -> running
[ConnectionManager:INFO] LSP connection established
```

### 5. Проверяйте capabilities

В sanity тестах выводятся возможности сервера:

```json
{
    "completionProvider": true,
    "hoverProvider": true,
    "definitionProvider": true
}
```

Убедитесь, что сервер поддерживает нужные функции.
